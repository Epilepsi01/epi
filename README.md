# epi — датасет ЭЭГ Nicolet (.e) для задачи эпилепсии

Пакет закрывает путь от папки с файлами `.e` до обучающей выборки: собирает
каталог метаданных, следит за изменениями на диске, даёт доступ к данным
пациента и нарезает сигнал на окна для обучения.

## Установка

Пакет **не публикуется на PyPI** и ставится из репозитория:

```bash
python -m venv .venv
./.venv/bin/pip install "epi-eeg @ git+https://github.com/unkwerror/epi.git"
```


## Данные пациентов

Записи ЭЭГ и всё производное от них (`catalog.sqlite`, `training/`, `plots/`,
`digest.json`, выводы ноутбука) содержат сведения о здоровье детей: GUID и даты
рождения пациентов, фамилии, заметки врачей. Всё это исключено из репозитория
через `.gitignore` и из дистрибутива через `MANIFEST.in`.

Перед коммитом или сборкой стоит убедиться, что данные не просочились:

```bash
python -m build
python - <<'PY'
import tarfile
print(tarfile.open('dist/epi_eeg-1.0.0.tar.gz').getnames())
PY
```

Выводы `demo.ipynb` нужно очищать перед коммитом — при выполнении в них
попадают GUID пациентов, даты рождения и заметки врачей.

## Быстрый старт

```python
from epi import Catalog, WindowSet, summary, render

catalog = Catalog("catalog.sqlite")
catalog.sync("/путь/к/данным")        # 1. обойти папки и собрать метаданные

catalog.patients()                     # 2. данные и метаданные пациентов
catalog.patient(ключ)                  # ключ можно указать началом GUID

windows = WindowSet(catalog)           # 3. обучающая выборка
windows.build()
windows.split()
x, y = windows.sample("train", n=512)

render(summary(catalog))               # 4. выжимка статистики
```

То же самое из командной строки:

```bash
python -m epi sync .                   # обновить каталог
python -m epi stats                    # статистика
python -m epi patient <ключ>           # всё об одном пациенте
python -m epi index                    # разметить окна
python -m epi index --gap-before 60 --gap-after 300   # с зазором у приступа
python -m epi index --merge-gap 120 --positives-per-event 1   # по окну на событие
python -m epi split                    # раздать пациентов по фолдам
python -m epi export --fold train --n 2000 --hard-ratio 0.5
python -m epi plot --type Seizure --n 3
```

Демонстрация всех возможностей с графиками — в `demo.ipynb`.

## Промежуток между окном и приступом

Каждое окно знает, насколько оно отстоит от ближайшего приступа: `lead_sec` —
секунды до начала следующего, `lag_sec` — секунды после конца предыдущего.
Ширина промежутка, который отделяет окно от приступа, задаётся раздельно с двух
сторон:

```python
windows = WindowSet(catalog, gap_before_sec=60, gap_after_sec=300)
```

Окна, оказавшиеся ближе, не годятся ни в один класс: перед приступом сигнал уже
меняется, после него держится постиктальное угнетение, — и назвать такое окно
фоном значит научить модель на заведомо неверной метке. Они получают метку `-1`,
не попадают ни в фолды, ни в выборку, но остаются в базе: `windows.windows(label=-1)`
покажет, что именно отбросили. Стороны разведены, потому что постиктальный хвост
заметно длиннее преиктального.

По умолчанию оба зазора нулевые, то есть разметка ровно такая же, какой была до
появления этих настроек.

Тот же зазор переводит выборку из задачи обнаружения в задачу прогноза:

```python
windows = WindowSet(catalog, gap_before_sec=300, preictal_sec=1800)
```

Положительными становятся окна, отстоящие от начала приступа на 5–35 минут:
ближе пяти минут прогноз уже бесполезен (предупредить никто не успеет), дальше
получаса сигнал неотличим от фона. Сам приступ и его окрестности уходят в
исключённые, фоном остаётся то, что дальше всего окна ожидания.

Те же параметры есть в командной строке: `--gap-before`, `--gap-after`,
`--preictal`.

## Приступ и событие

В разметке приступ — не маркер врача, а событие:

```python
windows = WindowSet(catalog, merge_gap_sec=120, positives_per_event=1)
```

`merge_gap_sec` склеивает приступы, между которыми меньше указанного числа
секунд. Короткая передышка между двумя разрядами — не фон: противопоставлять
окна оттуда самим приступам бессмысленно, а разметка «приступ — пауза — приступ»
учит модель искать границу там, где её нет. После склейки промежуток входит в
событие целиком.

`positives_per_event` ограничивает вклад одного события в выборку. Соседние окна
одного приступа перекрываются и отличаются сдвигом на шаг — десяток почти
одинаковых примеров даёт модели ровно столько же, сколько один, но весит в
десять раз больше, и всё это вес одного пациента в одну минуту его жизни.
Представителем события идёт окно, набравшее больше всего приступа (при разметке
под прогноз — ближайшее к его началу), остальные уходят в исключённые вместе с
теми, что событие лишь задели.

Нулевой `merge_gap_sec` (по умолчанию) всё же склеивает пересекающиеся маркеры:
два маркера на один приступ иначе посчитались бы дважды.

В командной строке: `--merge-gap`, `--positives-per-event`.

## Из чего набирается фон

Фоновых окон в сотни раз больше, чем положительных, и случайная выборка почти
вся приходит из спокойных часов. Модель на ней учится лёгкой задаче — отличать
приступ от сна, — а ошибается потом там, где сигнал на приступ похож:

```python
x, y = windows.sample("train", n=512, hard_ratio=0.5, hard_span_sec=600)
```

`hard_ratio` — доля фоновых окон, взятых вплотную к приступу: из полосы шириной
`hard_span_sec`, начинающейся сразу за зазором, с обеих сторон. При зазоре 60 с
до и 300 с после трудными окажутся окна за 60–660 секунд до приступа и через
300–900 секунд после него: остатки постиктального хвоста и преиктальный подъём,
то есть ровно то, на чём модель ошибается.

Если трудных окон в фолде меньше запрошенного, недостача добирается обычным
фоном — размер выборки от настроек не зависит. Сколько трудных нашлось на самом
деле, видно в печати `sample()`.

В командной строке: `--hard-ratio`, `--hard-span`.

## Кросс-валидация по пациентам

Для отбора модели используйте 5 фолдов **внутри сохранённого `train`**:
каждый пациент один раз попадает в валидацию, остальные четыре группы — в
обучение. Все записи и окна одного `patient_key` остаются вместе. Сохранённые
`val` и `test` в этот цикл не входят; `test` используется для финальной оценки
после выбора модели. Это [групповая кросс-валидация](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data).

Готовый пример с признаками ЭЭГ и обучением: [cross_validation.ipynb](cross_validation.ipynb).
Для уже размеченного каталога и сохранённого разбиения:

```python
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

from epi import Catalog, WindowSet
from epi.evaluation import patient_cv
from epi.features import eeg_features
from epi.preprocessing import preprocess

# Те же настройки WindowSet, с которыми была построена таблица windows.
windows = WindowSet(Catalog("catalog.sqlite"))
x, y, groups = windows.sample(
    "train", n=2000, seed=42, return_groups=True,
)
features, names = eeg_features(preprocess(x, windows.rate), windows.rate)

# Scaler обучается заново только на train каждого фолда.
model = make_pipeline(
    StandardScaler(),
    LogisticRegression(max_iter=2000, class_weight="balanced", random_state=42),
)
result = patient_cv(model, features, y, groups, n_splits=5, seed=42, verbose=True)
auc = result["summary"]["roc_auc"]
print(f'AUC = {auc["mean"]:.3f} ± {auc["std"]:.3f}')
```

`sample(..., return_groups=True)` возвращает ключ пациента **каждого реально
прочитанного окна**, в том же порядке, что `x` и `y`, после отбраковки и
перемешивания. Без этого флага прежний результат `(x, y)` сохраняется.
При дополнительном отборе окон одну и ту же маску нужно применять к трём
массивам. В новых экспортах `.npz` всегда есть `groups`:

```python
import numpy as np

with np.load("training/train.npz", allow_pickle=False) as data:
    x, y, groups = data["x"], data["y"], data["groups"]
```

Старые экспорты без `groups` нужно пересоздать: восстановить пациентов по
позициям перемешанных окон нельзя. CV видит только пациентов, представленных
в выбранных окнах; число пациентов проверьте через `len(np.unique(groups))`.

`patient_cv` создаёт свежую копию модели или Pipeline для каждого фолда.
Используется `StratifiedGroupKFold`: баланс классов по возможности сохраняется,
но пациенты не дробятся. `seed` воспроизводит разбиение; случайность самой
модели задавайте отдельно через её `random_state`.

Результат содержит:

- `folds`: AUC и остальные метрики, число пациентов, окон и положительных
  примеров в train/val каждого фолда.
- `summary`: невзвешенные `mean` и `std` каждой метрики по фолдам;
  `std` считается с `ddof=0`, как `numpy.std`. Поля `n_valid` и `n_folds`
  показывают, сколько значений вошло в расчёт.
- `overall`: метрики объединённых out-of-fold предсказаний. Это отдельная
  оценка, которая может отличаться от среднего AUC по фолдам.
- `scores`, `predictions`: out-of-fold предсказания в исходном порядке окон;
  `indices`: пары индексов `(train, val)` для проверки и повторения разбиения.

Если пациентов меньше пяти, число фолдов сокращается с предупреждением.
Нужны хотя бы два пациента. Если в train какого-либо фолда остался один
класс, обучение останавливается до первого `fit` с понятной ошибкой.
Если один класс остался только в val, AUC этого фолда равен `NaN`; он явно
исключается из среднего, а `n_valid` уменьшается. Балансировка групп не
гарантирует наличие обоих классов при малом числе пациентов.

Для своего цикла обучения, в том числе нейросети, используйте индексы:

```python
from epi.evaluation import patient_folds

for fold, (train_idx, val_idx) in enumerate(
    patient_folds(groups, n_splits=5, y=y, seed=42), start=1,
):
    x_train, y_train = x[train_idx], y[train_idx]
    x_val, y_val = x[val_idx], y[val_idx]
    # Здесь создать новую модель и оптимизатор, обучить и оценить на x_val.
```

Список словарей метрик своего цикла можно передать в `summarize_folds()`.
Порог классификации, отбор признаков, нормализацию между окнами и
`fit_quality_limits` нельзя обучать на всей выборке перед CV: используйте
только train текущего фолда. Фильтры `preprocess` с фиксированными параметрами
и `eeg_features` обрабатывают каждое окно независимо, поэтому в примере
рассчитаны до разбиения.

Среднее по фолдам уменьшает зависимость результата от одного набора
пациентов. `std` показывает разброс между группами, а не доверительный
интервал. Внутри фолда метрики считаются по окнам, поэтому пациенты с большим
числом окон всё ещё имеют больший вес. При балансированной выборке окон
PR AUC отражает именно её долю приступов.

## Диагностика ошибок чтения окон

Если отдельное окно не читается, `sample()` пропускает его и берёт следующий
кандидат. Обрабатываются ошибки индексации, ввода-вывода, конца файла,
ошибки чтения блока `pynicolet` и неполные массивы сигнала.
В лог `epi.windows` уровня WARNING записываются фолд, ID окна и записи,
путь файла, сегмент, начало и длина окна, метка, каналы, целевая частота,
исходное исключение и полный traceback. Это работает и при `verbose=False`.
Неожиданные ошибки вне чтения продолжают подниматься вызывающему коду.

Для сохранения диагностики локально:

```python
import logging
from pathlib import Path

Path("training").mkdir(exist_ok=True)
handler = logging.FileHandler("training/window-read.log", encoding="utf-8")
handler.setFormatter(logging.Formatter("%(asctime)s %(levelname)s %(name)s %(message)s"))
logging.getLogger("epi.windows").addHandler(handler)
```

В итоговой строке отдельно считаются плоские и нечитаемые окна. Если
кандидатов не хватило для квоты, предупреждение показывает запрошенное и
реальное число окон и положительных примеров. Если не осталось ни одного
окна, ошибка содержит оба счётчика.

## Что важно знать про эти данные

Решения в коде продиктованы свойствами самой коллекции, и без них результаты
будут неверными.

**Пациент опознаётся по GUID, а не по папке.** Имена папок содержат номера
выгрузок, а не личности: одна и та же подпись `Patient1` покрывала четырёх
разных людей. В коллекции 18 файлов, но 16 пациентов.

**Запись состоит из сегментов.** Файл `.e` может содержать несколько кусков,
разделённых настоящими разрывами во времени. Отсчёты читаются только внутри
одного сегмента, поэтому `start_sec` отсчитывается от начала текущего
сегмента, а время маркеров — от начала всей записи. Окно обучающей выборки
никогда не пересекает границу сегментов.

**Маркеры собираются из двух библиотек сразу.** Каждая ошибается по-своему:
`neo` верно раскладывает маркеры по сегментам, но многие типы оставляет как
`UNKNOWN` и портит кириллицу; `pynicolet` называет больше типов и правильно
декодирует текст, но в многосегментных файлах прижимает маркеры к концу
записи. `NicoletEReader` берёт от каждой то, что она делает верно.

**Названия типов маркеров берутся из четырёх источников подряд.** Готовые
таблицы производителя (девять типов у `pynicolet`, сорок два у `neo`)
покрывают только стандартные типы. Клиника заводит в NicoletOne собственные, и
их названия лежат прямо в записи, рядом с маркерами: `NicoletEReader` читает
эту таблицу из файла. Что не нашлось и там, доучивается голосованием по всей
коллекции. Из 21 типа маркеров сейчас опознаны 19; два оставшихся — служебные
отметки, которые система ставит парой каждые 15 минут, их названия хранятся не
в выгрузке, а в самой NicoletOne. Если подсмотреть их в списке событий штатной
программы, названия можно задать руками:

```python
catalog.sync(extra_names={"{32F2469E-6792-4CAD-8E11-B7747688BB8B}": "..."})
```

**Усечённые выгрузки добиты нулями.** Короткие сегменты в файлах `Pruned`
содержат сплошные нули, поэтому окно перед попаданием в выборку проверяется на
плоский сигнал (`max_flat`).

**Разбиение только по пациентам.** Окна одной записи перекрываются во времени
и тривиально предсказываются друг из друга, поэтому случайное разбиение самих
окон протащило бы тестовую выборку в обучение.

**Монтажи разные.** Число каналов от 21 до 30, частота 500 или 512 Гц. Для
обучения сигнал урезается до 19 электродов схемы 10-20, которые есть везде, и
приводится к 256 Гц.

## Текущее состояние коллекции

16 пациентов, 18 записей, 68 сегментов, 41.5 часа сигнала. 146 маркеров
приступов общей длительностью 76 минут — это 3% всего сигнала, хотя бы один
приступ есть у 15 пациентов из 16.

При окне 10 секунд с шагом 5 секунд получается 29 815 окон, из них 874 с
приступом (2.93%), разбиение 10 / 2 / 3 пациента.

## Открытые вопросы

Это не ошибки, а решения, которые стоит принять осознанно перед обучением.

- **Длина окна.** При 10 секундах 38 сегментов короче одного окна выпадают
  целиком. Медиана длительности приступа — 5.5 секунды, так что часть коротких
  событий размывается фоном.
- **Ширина зазора у приступа.** По умолчанию она нулевая, и фоном считается всё,
  что не приступ, — включая окно, снятое за секунду до него. Сколько секунд до и
  после приступа выбросить, зависит от того, что именно должна выучить модель, и
  решать это стоит до обучения, а не после.
- **Предобработка.** Сигнал отдаётся сырым, без фильтрации, с большими
  амплитудами. Фильтр и отбраковка артефактов пока не входят в пакет.
- **Размер валидации.** Для отбора модели доступна кросс-валидация по
  тренировочным пациентам через `patient_cv`; финальный `test` остаётся
  отдельным. Малое число пациентов всё ещё ограничивает точность оценки.
- **Аномалии разметки.** Самый долгий маркер приступа длится 1655 секунд
  (27 минут), что не похоже на приступ. У части пациентов дата рождения не
  раньше самой записи, поэтому возраст для них не считается.
